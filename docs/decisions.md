# Architecture Decision Records (ADR)

## ADR-001: Network Interception vs OCR

- **Проблема**: Как получать состояние игры.
- **Варианты**: Оптическое распознавание символов (OCR) с экрана или перехват сетевых запросов.
- **Решение**: Выбран перехват сетевых запросов (Network Interception).
- **Причина**: Сетевые ответы содержат чистый JSON, что исключает ошибки распознавания, работает быстрее и надёжнее.

## ADR-002: File-based persistence vs Database

- **Проблема**: Как хранить состояние, историю и стратегию.
- **Варианты**: SQLite, PostgreSQL, MongoDB или простые JSON-файлы.
- **Решение**: Файловая система (File-based persistence).
- **Причина**: ИИ-агенту (кодеру) и LLM (игроку) проще читать и править текстовые файлы. Отсутствуют зависимости базы данных.

## ADR-003: Provider-agnostic LLM abstraction

- **Проблема**: Зависимость только от одного LLM-провайдера (Gemini).
- **Решение**: Создан абстрактный `LLMProvider` с возможностью подключения Gemini, Groq, OpenAI через реестр.
- **Причина**: Гибкость, снижение расходов (возможность переключиться на Groq) и устойчивость к сбоям API.

## ADR-004: Markdown campaign input format

- **Проблема**: JSON сложно писать вручную для сложных стратегических кампаний.
- **Решение**: Использование Markdown в качестве входного формата для кампаний (парсится LLM-билдером в JSON).
- **Причина**: Markdown отлично читается людьми и легко интерпретируется моделями (LLM).

## ADR-005: Session-isolated war-room

- **Проблема**: Пересечение данных при запуске нескольких партий.
- **Решение**: Изолированные сессии `war-room/sessions/<session_id>/`.
- **Причина**: Позволяет параллельно или последовательно играть разные кампании без очистки файлов вручную.
- **Известный долг (v3.2):** Изоляция реализована не полностью — `strategy/`, `memory/` и `next_advisor_query.txt` всё ещё читаются из глобального `war-room/`, а не из папки сессии.

## ADR-006: Campaign как единственный источник идентичности агента

- **Проблема**: В системе существуют два дублирующихся источника "целей" — `constitution.md` / `crisis_handbook.txt` (legacy) и `Campaign` JSON (новый, v2.0+).
- **Варианты**: Оставить оба, удалить legacy-файлы, или авто-генерировать их из кампании.
- **Решение**: Удалить `constitution.md` и `crisis_handbook.txt` и опираться исключительно на Campaign JSON (`superGoal`, `priorities`, `constraints`, `victoryConditions`).
- **Причина**: Файлы сейчас — пустые заглушки, тратящие токены. Campaign JSON богаче и структурированнее. Устраняет дублирование и неоднозначность в промпте.
- **Статус**: Запланировано в v3.2 (P2).

## ADR-007: Strategy Plan генерируется из Campaign, хранится в сессии

- **Проблема**: Strategy Plan захардкожен в коде как дефолтный 4-фазный план (Stabilization → Economic Expansion → Regional Dominance → Global Power), не зависящий от конкретной кампании.
- **Варианты**: Сохранить один глобальный план; генерировать план из кампании при `init-campaign`; позволить пользователю вручную редактировать план.
- **Решение**: При `init-campaign` — вызывать LLM с промптом-шаблоном и сохранять сгенерированный `strategy-plan.json` в папку сессии (`war-room/sessions/<id>/strategy-plan.json`).
- **Причина**: Кампания "Россия 2050" с 50-летним горизонтом требует совсем других фаз, чем кампания "New Russia 2075". Привязка плана к сессии обеспечивает изоляцию между кампаниями.
- **Статус**: Запланировано в v3.2 (P1).

## ADR-008: Campaign-specific URL and Interactive Menu

- **Проблема**: Смешивание URL-адресов игр между разными кампаниями; неудобство переключения и создания кампаний из терминала; жесткая обрезка текста в TUI.
- **Решения**:
  1. `GAME_URL` сохраняется в индивидуальном файле `game_url.txt` в папке сессии активной кампании (`war-room/sessions/<campaign>/game_url.txt`).
  2. Внедрено интерактивное стартовое меню на базе `@inquirer/prompts` для выбора кампании, её создания (генерация `.md` шаблона с паузой на заполнение), ввода URL и сброса состояния.
  3. В TUI добавлена функция умного переноса/обрезания (`truncate`), избегающая деления слов.
- **Причина**: Повышение юзабилити, предотвращение путаницы с URL между параллельно идущими кампаниями, опрятный вид интерфейса.
- **Статус**: Реализовано в v3.3.
