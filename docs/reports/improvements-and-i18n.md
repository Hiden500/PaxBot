# Отчет: Интернационализация и архитектурные улучшения

## 1. Задачи по интернационализации (i18n)

В ходе анализа исходного кода были найдены захардкоженные строки, которые выводятся пользователю (в консоль и веб-интерфейс). Для полноценной поддержки мультиязычности их необходимо вынести в систему переводов.

### 1.0 Общая инфраструктура

- Внедрить библиотеку i18next в проект для управления переводами на клиенте и сервере.
- Настроить автоматический экстрактор ключей (например, `i18next-parser` или `i18next-scanner`) для выявления непереведенных строк на этапе CI.

### 1.1 Веб-интерфейс (`src/web/public/index.html`)

Файл содержит множество русскоязычных элементов интерфейса, которые нужно перевести:

- Заголовки и текст: `PaxBot Панель Управления`, `PaxBot: Настройка запуска`, `Настройте параметры кампании...`.
- Блоки меню: `📁 Кампания и игра`, `⚙️ Параметры ИИ`.
- Метки форм: `Выбрать кампанию:`, `GAME_URL (Ссылка на партию):`, `Провайдер LLM (LLM_PROVIDER):`, `Модель ИИ (LLM_MODEL):`, `API Ключ:`, `Base URL эндпоинта:`, `Язык ИИ:`, `Язык UI:`.
- Кнопки: `✨ Создать шаблон`, `🧹 Сбросить сессию`, `🚀 Запустить игру и авто-пилот`, `⚙️ Скомпилировать кампанию из MD`.
- Опции выпадающих списков: `Загрузка кампаний...`, `Загрузка моделей...`, `Свой эндпоинт (OpenAI Compat)`, `Google Gemini (по умолчанию)`.
- Состояния UI (JavaScript): `Кампании не найдены`, `Модели не найдены`, `Компиляция кампании с помощью LLM... Пожалуйста, подождите.`, `Шаблон новой кампании... создан...`, `Кампания... успешно скомпилирована...`.

### 1.2 Сервер веб-интерфейса (`src/web/server.ts`)

В коде отправки событий клиенту (socket.io) и генерации списка кампаний присутствуют хардкод-строки:

- `(Не скомпилирован, требуется MD)`
- `Файл Markdown не найден: ...`
- `Ошибка компиляции LLM: ...`
- `Кампания с именем ... уже существует.`
- `Ошибка создания кампании: ...`

### 1.3 Логика игрового цикла и "Мозга" (`src/loop.ts`, `src/brain/action-generator.ts`, `src/brain/response-parser.ts`)

Часть логов и статусов, отправляемых в TUI State, до сих пор на русском:

- В `loop.ts`: `[Ошибка] Ошибка хода ...`
- В `action-generator.ts`: `Мозг: Сбор контекста...`, `[Мозг] Фаза 2: Сбор контекста из файлов War Room...`, `Мозг: Сборка промпта...`, `[Мозг] Фаза 3: Сборка промпта...`, `Мозг: Ожидание ответа LLM...`, `[Мозг] Запрос к LLM...`, `[Мозг] LLM ответила...`, `Мозг: Анализ ответа...`, `[Мозг] Леджер обновлен...`.

## 2. Предложения по архитектурным и техническим улучшениям

Основываясь на текущей документации (`docs/architecture.md`, `docs/todo.md`, `docs/PRD.md`) и изучении кода, предлагаются следующие улучшения:

### 2.1 Развитие архитектуры (Multi-agent)

В текущей версии (Single-agent) цикл управляется одним модулем Brain.

- **Разделение ролей**: Переход к мультиагентной архитектуре (Strategist → Planner → Critic → Executor).
- **Внедрение Critic Module**: Добавить этап самопроверки (оценка сгенерированных действий перед передачей в Executor) для снижения риска ошибок и бессмысленных ходов.
- **Внедрение Risk Engine**: Система формализованного аудита рисков на основе анализа состояния карты.

### 2.2 Модуль памяти и промпты (Token Bloat Protection)

- **Лимитирование истории в промпте**: По мере прохождения игры `achievements` и `lessonsLearned` разрастаются, увеличивая риск исчерпания контекстного окна LLM (token bloat). Необходимо внедрить алгоритмы агрегации (суммаризации старых уроков) и ограничить количество передаваемых элементов памяти в `memory/loader.ts`.
- **Вынос системных промптов**: Вынести огромный системный промпт LLM из кода (`src/brain/context-assembler.ts`) в отдельные `*.md` или `*.txt` файлы, что упростит их редактирование и версионирование.

### 2.3 Технический долг и рефакторинг

- **Централизация конфигурации**: Вынести жестко закодированные таймауты (например, в `src/hand/actions-ui-helpers.ts` и `src/hand/navigate.ts`) в единый конфигурационный файл `BROWSER_CONFIG`.
- **Управление окружением**: Устранить дублирование логики загрузки и обновления переменных среды (в `server.ts` и `boot.ts`), создав единый сервис `src/shared/env-loader.ts`.
- **Надежность парсинга**: При захвате трафика (в `src/spy/capture.ts`) использовать `TextDecoder` для расшифровки вместо жестко закодированной `utf-8`, что предотвратит потенциальные проблемы с кодировками при изменениях на стороне сервера игры.

### 2.4 Тестирование и CI/CD

- **Метрики качества**: Интегрировать систему сбора KPI (согласно плану v4.0), чтобы оценивать результативность LLM в разных кампаниях.
- **Исправление багов CI**: Исправить проблему с импортом `dotenv` в тестах Vitest (переход на `esModuleInterop` или корректировка импортов), которая указана в `todo.md`.
- **E2E Тесты**: Добавить сквозные Playwright-тесты для нового веб-интерфейса, чтобы предотвратить регрессии при изменении UI и Socket.IO событий.
